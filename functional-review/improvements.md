# Product gaps and improvements

Observed in a local isolated workspace against baseline a182328. Admin/account personas do not apply: there are no accounts or shared backend. Category A/B changes below are implemented; category C items are proposals, not completion claims.

| Class / priority | Observed problem, users and evidence | Solution and benefit | Effort / dependencies / tradeoffs | Recommendation |
|---|---|---|---|---|
| A / first | Returning users lose clear state, batched changes, pricing row identity or unread original records. Reproduced in tests; F01–F04/F06/F17. | Correct persistence and row ownership; visible unsaved state and separate raw recovery download. Users can keep and recover their work. | Existing hooks/model only; drafts remain tab-local when storage fails. Multi-key operations are not transactional. | Implemented; tests and browser evidence in coverage. |
| A / first | Invalid imports, stale scans and unchecked scraper connections compromise normal workflows. Reproductions F03/F05/F07/F08/F18–F20. | Validate before use, cancel obsolete scans, pin public addresses at connection time and bound work. Preserves legitimate legacy imports and relative social links. | Existing API/Node transport, no new dependencies. Live deployed behavior still needs authorized verification. | Implemented. |
| A / next | Backups omit history; comparisons omit sources/current version; false default evidence and focus loss. Observed F09–F14. | Full history backups; compare to current; complete content diff; truthful source and focus behavior. | User approved history policy (“whatever is best”): full backups replace history, legacy imports preserve it; confirmed clear/reset delete history. | Implemented and explained in Settings. |
| B / next | First-time users cannot name their existing business profile without editing JSON. Missing control confirmed by failing test. | Settings business-name field saves the existing model; positioning/pricing can identify the user's business. | One existing input/profile setter; saves as typed like existing profile controls. No schema or scope expansion. | Implemented; reload test. |
| B / next | Padded search fails and corrected imports cannot retry the same selected file. Reproduced F15/F16. | Trim search consistently; reset file picker after each attempt. Removes avoidable dead ends. | Existing controls only; no dependencies. | Implemented. |
| C / first | About/README team and monitoring expectations exceed local-only storage and manual preview controls. Evidence: no accounts, synchronization, scheduler or social/news integration. Demand for these features is unvalidated. | Decide whether to narrow public promises or fund shared workspaces and scheduled monitoring. Reliable team use requires identity, permissions, synchronization, delivery and failure handling. | Substantial backend/services and business/privacy decisions; recurring cost and data ownership. | Validate need first; owner approval before implementation or changing commitments. |
| C / next | Separate tabs can edit stale workspace copies; no conflict detection. Code confirms no storage-event reconciliation; real multi-user demand unknown. | Define conflict behavior and add tab-aware synchronization or explicit conflict recovery. Prevent silent overwrites during simultaneous work. | Storage synchronization and merge policy; blind last-write merging can lose changes. | Validate first; product decision required for merge rules. |
| C / next | Import immediately replaces workspace; raw recovery export requires manual repair. Observed current controls and malformed-data cases. | Preview import totals/conflicts and offer a recovery assistant. Makes replacement/recovery easier to understand. | New workflow and partial-record acceptance policy; must not hide dropped records or silently change retention. | Defer until core fixes are accepted; approve recovery rules first. |

The scraper transport follows Node's documented [HTTP custom lookup option](https://nodejs.org/api/http.html#httprequesturl-options-callback) and [HTTPS request/TLS options](https://nodejs.org/api/https.html). Connection pinning is a security fix to existing public-page extraction, not a new monitoring service. No external communication or deployment occurred.
